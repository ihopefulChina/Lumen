# Lumen v0.0.3 Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Ship Lumen 0.0.3 (3) with the known correctness, safety, transfer-lifecycle, and Finder-style interaction defects fixed and verified end to end.

**Architecture:** Preserve the existing SwiftUI application, OSSClient, and TransferEngine, while adding small testable boundaries for HTTP transport, request identity, file safety, and transfer-owned resources. State commits become context-checked, destructive actions fail safely, and grid/list interactions share deterministic selection semantics.

**Tech Stack:** Swift 6, SwiftUI/AppKit, Observation, URLSession, Swift Testing, Xcode 26, Aliyun OSS V4 signing, GitHub Releases.

## Global Constraints

- Deployment target remains macOS 15.0, Apple Silicon arm64.
- Release version is exactly 0.0.3; build number is exactly 3.
- Release asset is exactly Lumen-0.0.3.dmg and tag is exactly v0.0.3.
- Real OSS writes are restricted to lumen-v003-smoke/ and that prefix must be empty after verification.
- Release continues to use ad-hoc signing and must not claim Apple notarization.
- Do not introduce third-party dependencies, Finder column view, tags, or unrelated architecture rewrites.
- Cancellation is silent; real errors may expose OSS code/message/request ID but never credentials or signed query contents.
- Run each test red before implementation and green after implementation.
