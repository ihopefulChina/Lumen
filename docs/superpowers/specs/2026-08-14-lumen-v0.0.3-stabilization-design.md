# Lumen v0.0.3 稳定化与 Finder 风格交互设计

## 背景与目标

Lumen 当前版本为 `0.0.2 (2)`。现有代码可以构建并通过 24 个基础单元测试，但浏览请求、传输任务、文件路径、安全作用域资源、对象重命名、冷启动文件打开和部分界面状态存在竞态或资源生命周期缺陷；浏览器交互也没有形成 macOS Finder 一致、可预测的反馈。

本次发布目标是 `0.0.3 (3)`：修复已发现的稳定性、安全性和交互问题，补齐关键回归测试，用受限的真实 OSS 前缀完成端到端冒烟测试，更新 README，生成并发布 `Lumen-0.0.3.dmg`。发布前不得保留已知的阻断级或高风险缺陷。

## 产品原则与范围

- 采用稳定化修复，不重写应用，也不替换 SwiftUI、`OSSClient` 或 `TransferEngine` 的整体架构。
- 界面遵循 Finder 的心智模型：即时反馈、单一明确选择、标准键盘语义、直接操控、克制动画和可预测导航。
- 使用系统控件、系统材质和 SF Symbols；保留现有视觉身份，不进行无关的品牌重设计。
- 不新增 Finder 分栏视图、标签、复杂拖动排序或自定义物理动画。
- 不做与本次缺陷无关的大范围 `AppModel` 拆分，只提取能够建立可测试边界的小型组件。
- 取消属于正常控制流，不显示错误；真实错误应包含可操作信息，但不得泄露 AccessKey、签名或其他凭据。

## 架构边界

### 浏览请求身份与状态提交

每次账户、Bucket、前缀或检查器目标变化都生成新的请求身份。异步响应只有在请求身份仍与当前上下文一致时才允许提交到 UI；旧请求应主动取消，即使底层请求来不及取消，迟到结果也必须被丢弃。

浏览刷新保留当前内容并显示轻量进度，而不是先清空造成界面闪烁。切换账户或 Bucket 时，所有依赖旧上下文的选择、检查器和待提交请求立即失效。主选择必须确定性产生，不能依赖 `Set` 的无序迭代。

### 可注入网络层

`OSSClient` 通过一个最小会话协议接收请求，以便生产环境继续使用 `URLSession`，测试环境注入确定性的响应、错误和延迟。签名、URL 构造、错误解析、分页与 multipart 控制逻辑均可在无公网环境下覆盖。

### 传输资源生命周期

每个传输任务对安全作用域访问、临时文件、multipart upload ID 和最终状态拥有明确且仅一次的释放责任：

- 排队中、运行中、重试或取消都必须走统一清理路径。
- HEIC 转换、剪贴板和照片导入产生的临时文件在任务终止后删除。
- iCloud 文件必须等待下载完成并重新读取元数据后再规划上传。
- 目录枚举、文件探测和图像转换不得阻塞主线程。
- multipart 失败或取消必须尽力调用 abort；abort 的次级失败可记录，但不得覆盖原始错误。
- 并发槽在所有终止路径上归还，取消排队任务不会泄漏资源或阻塞后续任务。

### 文件安全边界

所有本地目标路径通过一个集中式安全组件解析。解析后的真实父路径必须位于用户选择的下载根目录内；拒绝 `..`、绝对路径、非法空组件以及通过符号链接越界的目标。创建目录和写文件前后都进行范围验证。

本地同名文件默认跳过并形成摘要，不静默覆盖。远端上传冲突先展示汇总确认；重命名目标已存在时必须明确确认，名称为空、包含 `/` 或不满足单对象名称要求时立即拒绝。重命名采用 copy 后 delete，但只有 copy 已确认成功时才能删除源对象。

## Finder 风格交互

### 选择与打开

网格和列表共用一套选择协调逻辑：

- 指针按下立即产生可见的按压或选择反馈。
- 单击选择；`Command` 单击增删选择；`Shift` 单击形成连续范围；点击空白区域清除选择。
- 双击文件夹时先保留可感知的首击反馈，再进入文件夹。导航开始后显示目标路径加载状态，不出现“像没有选中”的空反馈。
- 双击文件执行系统默认打开行为；上下文菜单始终作用于被点击项，必要时先将该项纳入选择。
- 方向键移动焦点，`Shift` 扩展范围，`Space` 打开快速查看，`Return` 发起重命名，`Delete` 进入删除确认，`Escape` 清除选择或取消当前瞬时操作。
- 焦点环、选中态和不可用态使用系统语义，并在深浅色模式下保持足够对比度。

列表空白区域保持干净，不渲染类似虚假条目的占位行。列表行保持原生表格对齐、排序和选中语义；网格单元使用一致的点击区域、标签截断和键盘焦点。

### 导航与工具栏

后退、前进和当前位置形成左侧导航组；视图切换、搜索和检查器形成右侧操作组。路径栏清晰展示当前位置，并可作为拖放目标。加载过程中保留旧内容并降低强调，同时显示系统进度反馈；失败后保留可恢复上下文并提供重试。

侧边栏中账户是上下文分组，Bucket 是唯一表示当前内容位置的选择，避免账户与 Bucket 同时呈现竞争性的高亮。Bucket 切换后路径回到根前缀，并清理旧选择。

### 拖放、检查器与传输

拖入文件时，目标文件夹或路径片段在悬停期间明确高亮，离开后立即恢复；最终上传前缀必须与视觉目标一致。检查器按“摘要、元数据、链接、操作”分区，明确区分当前可见数量与服务端总数，危险操作独立放置且不成为默认按钮。

传输托盘使用原生折叠、进度和状态表达，取消和重试仅在合法状态出现。设置页与账户页保持系统表单语义，降低密度；公共读权限等高风险选项必须有清晰警示。所有非必要动画响应“减少动态效果”设置，信息不依赖动画或颜色单独传达。

## OSS 行为与错误处理

- 对象 URL 必须保留完整 key，包括连续斜杠、空格、Unicode、`+`、`#`、`?` 和其他需编码字符，不得通过拆分重组改变对象身份。
- Markdown 和 HTML 链接文本分别进行正确转义；复制链接不会产生指向其他 key 的 URL。
- 自定义 endpoint 的 scheme、host 和 port 按账户配置保留；host/path 风格只按既有规则选择。
- OSS 非成功响应保留状态码、服务端错误 code、message 和 request ID。下载错误也必须解析响应体。
- 列举分页若不完整或 continuation token 异常，界面标记结果不完整；删除等破坏性批量动作在数据不完整时 fail-safe。
- 应用版本解析严格拒绝非法版本组件，更新资源只接受当前仓库 release 中安全、精确命名的 DMG。
- 账户持久化和密钥持久化失败必须反馈给用户；内存状态只在写入成功后更新。

## 应用生命周期

Finder 或 Dock 在冷启动时交给应用的 URL 先进入待处理队列。主会话和窗口准备完成后按顺序消费，不能因尚无焦点窗口而丢失。菜单栏显示设置变更立即生效，不依赖传输计数变化触发刷新。

快速查看、缩略图缓存和临时预览文件在正常关闭、替换目标和异常结束时有界清理，不删除用户原始文件。

## 测试策略

### 单元测试

覆盖版本解析、对象 URL、Markdown/HTML 转义、名称验证、安全下载路径、符号链接越界、主选择确定性、上传路径规划、临时资源清理、菜单栏派生状态和错误正文解析。

### 模拟网络集成测试

使用注入会话验证：

- 迟到的 Bucket、前缀和检查器响应不能覆盖当前状态。
- 分页完整与异常 token 的处理。
- 单段与 multipart 上传，请求签名输入、分片失败、取消和 abort。
- 下载错误正文和 request ID 保留。
- 重命名 copy 成功后 delete；copy 失败绝不 delete；目标冲突需确认。
- 排队取消与运行取消都只清理一次，并归还并发槽。

### UI 与人工交互检查

至少覆盖网格和列表的单击、双击、修饰键多选、键盘移动、快速查看、重命名、删除确认、上下文菜单、拖放悬停、前后导航、加载和错误恢复。检查浅色、深色、高对比度、减少动态效果与完整键盘访问；对无法稳定自动化的部分保留发布前人工清单。

### 真实 OSS 冒烟测试

只允许使用前缀 `lumen-v003-smoke/`，流程包括：

1. 上传一个小文件。
2. 上传一个大于 8 MB、触发 multipart 的文件。
3. 上传包含空格、Unicode、`+` 和连续路径分隔语义的特殊 key。
4. 列举并下载，逐字节核对内容。
5. 重命名并验证旧 key 消失、新 key 内容一致。
6. 验证生成链接的编码与对象身份一致。
7. 删除本次创建的全部对象。
8. 最终列举确认该前缀为空。

测试不得访问、修改或清理此前缀以外的对象。
