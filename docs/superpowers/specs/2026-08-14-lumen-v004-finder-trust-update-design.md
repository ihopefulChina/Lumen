# Lumen 0.0.4 Finder、可信传输与自动更新设计

## 目标

把 Lumen 从“可用的 OSS 浏览器”推进为更接近访达的日常整理工具，同时先补齐凭证、传输完整性和应用更新三条信任链。0.0.4 只覆盖同一 Bucket 内的云端整理；跨 Bucket、全 Bucket 搜索、对象标签、历史版本恢复和持久化断点续传留给后续版本。

## 范围

### 1. Keychain 凭证

- 新保存的 AccessKey Secret 与 STS Token 只写入 macOS Keychain。
- 启动时对旧 `secrets.json` 做逐项迁移：只有某项成功写入并回读 Keychain 后才从明文文件删除；全部迁移成功后删除空文件。
- 迁移失败时保留原明文，不静默丢失凭证，并在账号连接时显示可操作错误。
- 删除账号时同时删除 Keychain 中对应的 Secret 和 Token。
- `accounts.json` 继续只保存非敏感账号配置。

### 2. CRC64/XZ 完整性校验

- 新增流式 CRC64/XZ 实现，已知向量 `123456789` 必须得到 `0x995DC9BBDF1939FA`。
- 普通上传、分片上传完成和完整下载均读取 OSS 返回的 `x-oss-hash-crc64ecma`。
- 服务端返回校验值时，本地结果必须相同，否则任务失败且下载临时文件不得落到最终目标。
- 老对象或图片处理响应未返回 CRC64 时保持兼容，不把“服务端无校验值”误判为失败。
- 传输任务显示“已校验”状态；失败信息明确区分网络错误与完整性错误。

### 3. 同 Bucket 云端整理

- 对象和文件夹支持拖到当前列表中的目标文件夹，默认执行移动。
- 对象快捷菜单增加“移动到当前文件夹”和“复制到当前文件夹”的可用入口；路径栏可作为目标。
- 单个对象移动使用服务端 Copy + Delete，复制只使用 Copy，并禁止静默覆盖。
- 文件夹重命名、移动和复制以完整前缀为单位：先列出全部对象、拒绝不完整分页、验证目标不在源目录内部、预检目标冲突，再复制；移动仅在所有复制成功后删除源对象。
- 复制阶段失败时尽力清理本次已创建的目标对象，源对象保持不动。
- 文件夹占位对象也参与迁移；空文件夹仍然存在。

### 4. 排序与收藏夹

- 排序字段：名称、修改日期、大小、种类；方向：升序、降序。
- 文件夹默认置顶，并在名称字段下使用本地化自然排序；设置按账号会话持久化。
- 列表表头与工具栏排序菜单共享同一排序状态，网格和列表结果一致。
- 当前 Bucket 路径可加入侧边栏收藏夹；收藏记录 `accountID + bucketName + prefix`，不复制或移动云端对象。
- 点击收藏自动切换账号、加载 Bucket 并进入路径；失效收藏显示错误但不会被静默删除。
- 收藏支持重命名显示名称、拖动排序和移除；0.0.4 至少交付添加、打开、移除和稳定持久化。

### 5. Sparkle 自动更新

- 使用 Sparkle 2.9.2，通过 Swift Package Manager 固定精确版本。
- 公开版延续 0.0.3 的非沙盒数据位置，避免升级后账号配置被隔离到新容器；Sparkle 使用其官方支持的非沙盒安装路径。
- 更新 Feed 固定为 `https://github.com/ihopefulChina/Lumen/releases/latest/download/appcast.xml`。
- 发布包使用 Sparkle EdDSA 私钥签名，公钥嵌入 `Info.plist`，并开启提取前签名验证。
- 菜单和设置中的“检查更新”统一调用 Sparkle。发现版本后，用户点击安装即由 Sparkle 下载、替换应用并自动退出重启，不再只打开 DMG。
- 自动检查开关继续由 Lumen 设置控制；关闭后不做后台检查，手动检查仍可用。
- 0.0.4 是首个包含 Sparkle 的版本，因此从 0.0.4 开始支持后续原地更新；0.0.3 用户仍需手动安装 0.0.4 一次。

> 发布审查修正：原设计计划启用沙盒 Installer XPC，但 0.0.3 的公开 DMG 在最终签名时并未携带沙盒 entitlement。直接切换会改变 Application Support 目录并让现有账号不可见，因此 0.0.4 保持分发兼容性；待具备 Developer ID 签名和显式容器迁移后再单独启用沙盒。

### 6. 发布

- 版本更新为 `0.0.4`，构建号 `4`。
- 发布资产包含 `Lumen-0.0.4.dmg` 与 `appcast.xml`。
- README 增加云端整理、排序、收藏夹、CRC64、Keychain 和自动更新说明，并明确 0.0.3 到 0.0.4 需要最后一次手动更新。
- GitHub Release 必须为公开 Latest、非草稿、非预发布；远端重新下载的 DMG 哈希必须与本地一致。

## 架构

- `SecureSecretStore` 负责 Keychain CRUD 和一次性明文迁移，账号层只依赖它的窄接口。
- `CRC64XZ` 是无 UI 的流式校验器；`OSSClient` 在网络响应落地前完成比较，并把校验结果传给 `TransferEngine`。
- `CloudObjectOperation` 负责前缀规划、冲突预检、复制、回滚和移动删除；`AppModel` 只负责选择、进度和提示。
- `BrowserSortDescriptor` 与 `FavoriteLocationStore` 是可独立测试的状态模型；SwiftUI 视图只绑定状态。
- `AppUpdater` 封装 Sparkle 控制器，替代现有 GitHub API 下载器，避免 UI 直接依赖第三方类型。

## 错误与安全策略

- 任何复制、重命名或移动都默认禁止覆盖。
- 文件夹列表达到分页上限时禁止继续移动、复制或重命名。
- Keychain 迁移、CRC64 不一致、Sparkle 签名失败均属于阻断错误，不以警告代替失败。
- 删除源对象永远排在所有目标对象成功复制之后。
- 更新 Feed 与资产只允许 HTTPS 和本仓库固定路径；更新归档必须通过 EdDSA 验证。
