# Lumen 0.0.5 访达式编辑与升级发布设计

## 目标

0.0.5 聚焦两件每天都能感知的事情：让文件名编辑真正像 macOS 访达，并消除搜索过滤后仍可误操作隐藏项目的风险。这个版本同时作为 0.0.4 内置 Sparkle 之后的第一次真实升级，必须证明公开更新 Feed、签名安装包和 GitHub Latest 发布链路可以把旧版本安全带到 0.0.5。

## 已确认问题

### 搜索后的隐藏选择

`BrowserModel.searchText` 只参与 `visibleFolders` 和 `visibleObjects` 的派生过滤，没有同步收敛 `selectedKeys`、`focusedKey` 或 `selectionAnchorKey`。与此同时，删除、下载、云端复制和拖放等动作会读取原始选择。因此可以稳定复现：先选择 `a.txt`，再搜索只匹配 `b.txt` 的内容，界面不再显示 `a.txt` 的高亮，但旧选择仍可能成为后续动作的目标。

根因是浏览模型缺少“选择必须属于当前可见集合”的状态不变量，而不是某一个按钮忘记检查选择。修复必须在模型边界建立该不变量，并在动作派生值上增加防御，不能只禁用某一个菜单项。

### 重命名不像访达

网格和列表当前都通过模态 Alert 输入新名称，Return 键则直接打开选中项目。访达的熟悉行为是：单击保持即时高亮，Return 在原位置编辑名称，Enter 提交，Esc 取消，双击或 `⌘↓` 打开。模态 Alert 会把用户从对象所在位置抽离，也无法在提交失败时自然保留编辑上下文。

## 交付范围

### 1. 可见选择不变量

- `selectedKeys`、`focusedKey` 和 `selectionAnchorKey` 在搜索词、素材过滤条件、目录内容或路径发生变化后，只能引用当前可见项目。
- 搜索词改变后，仍匹配的选择保留；不再匹配的选择、焦点和范围锚点立即移除。
- `selectedObjects` 与 `selectedFolders` 只能从可见数组派生，形成第二层保护。
- 进入其他文件夹、后退、前进或切换 Bucket 时清空当前文件夹搜索，避免把上一层过滤条件无提示地带进新位置。
- 搜索框提示改为“搜索当前文件夹”；底部状态栏在搜索时显示“找到 N 项”，有选择时仍优先显示“已选 N 项”。

### 2. 访达式就地重命名

- 只有一个可见项目被选择时才可开始重命名；多选、空选择、加载中或云端整理中不进入编辑。
- Return 对单个选中项目开始就地重命名，不再打开项目。
- 文件夹名称整体选中；文件名称默认只选中最后一个扩展名前的主文件名，例如 `photo.final.png` 选中 `photo.final`，没有扩展名时选中全部。
- 网格和列表共用同一重命名会话；切换视图时编辑状态与草稿不丢失。
- Enter 提交，Esc 取消。单击其他项目、切换路径或项目从刷新结果中消失时取消当前编辑。
- 提交期间字段保持在原位置并暂时不可重复提交。名称本地校验或云端冲突失败时保留编辑会话与草稿，同时显示现有错误提示；成功后刷新并选中新键。
- 快捷菜单中的“重命名…”改为选中目标并进入同一就地编辑，不再弹出 Alert。
- 双击行为保持：文件夹进入，文件快速查看。新增 `⌘↓` 打开选中项目；`⌘O` 继续用于上传，避免破坏现有工作流。
- Esc 的优先级是先取消重命名，再取消普通选择。Delete 与现有删除确认保持不变。

### 3. 自动更新与发布

- Sparkle 固定为 2.9.2，Feed 继续使用 `https://github.com/ihopefulChina/Lumen/releases/latest/download/appcast.xml`。
- 设置中的“检查更新…”在 Sparkle 暂不可检查时禁用，并说明安装完成后 Lumen 会自动退出并重新打开。
- 版本更新为 `0.0.5`，构建号为 `5`；发布资产为 `Lumen-0.0.5.dmg` 和 `appcast.xml`。
- appcast 必须同时保留 0.0.5 与 0.0.4 条目，0.0.5 enclosure 使用现有 Sparkle Ed25519 密钥签名，声明长度与 DMG 字节数一致。
- GitHub Release 必须为公开、非草稿、非预发布并成为 Latest。远端重新下载的 DMG 和 appcast SHA-256 必须与本地发布资产一致。
- 发布后从 Latest 下载地址重新读取 Feed，确认 build 5 是最高版本、下载 URL 指向 v0.0.5、签名可验证，从而覆盖 0.0.4 检查更新到 0.0.5 的真实服务端路径。

### 4. README 与发布说明

- README 下载链接、系统要求和版本描述更新为 0.0.5。
- 功能说明加入就地重命名、搜索选择安全和新的 Return / `⌘↓` 行为。
- 自动更新章节明确：0.0.4 用户可直接在软件内升级到 0.0.5，安装完成后 Lumen 自动重新打开；0.0.3 及更早版本仍需先手动安装新版本。
- `docs/releases/v0.0.5.md` 记录新功能、修复、安全策略、系统要求和最终 DMG SHA-256。
- 应用图标及其画布、主体尺寸在 0.0.5 不变，避免无关视觉改动和打包体积回归。

## 架构

- `BrowserModel` 持有纯状态的 `BrowserRenameSession`，负责选择不变量、开始/取消/完成编辑及扩展名选择范围。它不执行 OSS 网络请求。
- `BrowserView` 根据会话键在网格或列表名称位置渲染同一个 `FinderRenameField`。字段只负责 AppKit 文本编辑、焦点、选区和 Enter/Esc 回调。
- `AppModel.rename` 与 `renameFolder` 返回成功布尔值。视图仅在返回成功时结束会话；失败沿用 Banner 错误通道并保留草稿。
- `LumenActions` 增加重命名和打开选中项动作；全局按键监听在文本字段是第一响应者时不截获按键，避免干扰输入法和编辑命令。
- 版本、打包、Feed 生成继续使用现有 Xcode 与 `scripts/package-dmg.sh` 链路，不引入新的更新框架或发布服务。

## 状态与数据流

1. 用户单击项目，浏览模型建立单选和焦点。
2. Return 或快捷菜单请求开始重命名；模型确认当前只有一个可见选择并创建会话。
3. 名称单元格切换为 AppKit 编辑字段，字段在成为第一响应者后应用主文件名选区。
4. Enter 把草稿提交给对应的对象或文件夹重命名方法。提交成功后刷新列表、选中新键并结束会话；失败时保留字段。
5. 搜索、过滤、刷新或导航改变可见集合时，模型先收敛选择；若编辑目标不再可见则取消会话。

## 错误与安全策略

- 不允许隐藏选择参与删除、下载、复制、移动或检查器信息。
- 重命名继续禁止静默覆盖，并沿用完整前缀检查、复制成功后再删除源对象的现有策略。
- 空名称、路径分隔符和非法名称在发起 OSS 请求前失败。
- 提交进行时禁止第二次提交；用户仍能看到正在整理云端项目的状态。
- 发布脚本继续拒绝覆盖已存在的本地 0.0.5 资产，继续检查非沙盒兼容、无意外 entitlement、代码签名、DMG 挂载和 Sparkle 签名。

## 测试与验收

- 单元测试先复现隐藏选择：搜索排除已选项后，选择、焦点、锚点和动作派生数组均不再包含它。
- 单元测试覆盖搜索保留仍可见选择、导航清空搜索、素材过滤收敛选择、文件主名称选区、文件夹全选区、多选拒绝编辑、取消与提交状态。
- AppModel 测试覆盖重命名成功返回 true、校验或 OSS 冲突返回 false，并验证失败不结束编辑会话。
- Debug 全量测试必须通过；真实 OSS 冒烟仅在现有凭证可非交互访问时执行，凭证不可用时不得尝试写入并要在发布清单中如实记录。
- Release clean build、静态分析、DMG 挂载、深度签名验证、启动和 Sparkle 初始化必须通过。
- 发布后验证 GitHub Release 属性、远端哈希、Latest appcast 内容、enclosure 长度和 Ed25519 签名。

## 非目标

0.0.5 不实现全 Bucket 服务端搜索、跨 Bucket 移动、标签管理、对象历史版本、回收站或持久化断点续传。这些功能需要独立的数据、安全或发布设计，不与本次交互修复捆绑。
